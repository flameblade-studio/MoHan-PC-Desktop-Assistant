# 墨寒角色外觀包 ／ 墨寒角色外观包 ／ MoHan Character Appearance Packs ／ 墨寒キャラクター外観パック

## 繁體中文

角色外觀包是單一、自含、可直接上傳與下載的 ZIP 相容 `.mohan-outfit` 容器。使用者只需下載並選取一個檔案；允收內容限定為該檔案內的自含素材與 manifest。每項 PNG、WebP 或安全 SVG 都必須在同一 archive，由 manifest 以 SHA-256、尺寸、anchor、z-order 與穩定 slot 完整引用。匯入只接受引用完整、唯一、齊備、權限相符且安全的成員，完整驗證後再於同一目的目錄原子安裝；任何未完成結果都維持隔離，既有版本保持完整。安裝負責加入內容，預覽、啟用、套用與保存由 UI 的全域 Save/Cancel 流程控制。

一包可同時包含多件衣裝及色系、髮型、頭飾、妝容和配件，也可只含純衣裝、純髮型、純頭飾或純妝容。穩定選擇槽為 `garment`、`hairstyle`、`headwear`、`makeup`、`weapon`、`handheld`、`jewelry`、`foreground-effect`；各槽以 `category/pack_id/item_id/variant_id` 分開列舉、保存、解析與移除保護，所以長劍／短劍與劍鞘、手持物、珠寶及前景效果可以同時存在並跨包混搭。Manifest 的單一 `accessories` 集合中，每個 item 必須宣告明確 `accessory_kind`。Typed `ensemble` 必須涵蓋衣裝、髮型、頭飾與四個配件槽；衣裝與髮型必須指定同包項目，頭飾及四個配件槽可明確為 `none`；`makeup` 可省略（沿用使用者目前的妝容）或明確為 `none`（素顏）。一鍵套用後仍可逐槽改選。Ensemble 的變更範圍限定為外觀；臉型、五官、身份與核心提示詞由核心持續掌握。

衣裝以官方二代素體 `mohan-body-v2` 為準；為一代素體 `mohan-body-v1` 製作的套件維持在匯入與執行範圍之外，並須以 `tools/build_outfit_pack.py` 對二代範本重建（雲端一鍵製衣會直接產出二代套件）。官方美術規格為成人女性，168 公分、54 公斤、86/71/62/90 公分，約 C70-equivalent；數值的用途限定為官方美術製作與驗收。真正相容性由版本化 rig anchors、masks 與 geometry 判斷。肩頸線、胸廓、腰胯線、四肢比例、膚色和本體輪廓都由核心掌握。外掛的有效範圍是以 `visible`／`covered` 宣告官方膚色區域，並從 `structured`、`draped`、`stretch`、`loose` 選擇布料行為；臉型、膚色與身材由核心持續掌握。

衣裝必須完整覆蓋 v2 的 31 個精確視角：既有七個演出輪廓 `cheek-rest`、`left-neutral`、`front-crossed`、`front-mock-scold`、`front-mock-hit`、`front-eureka`、`front-exasperated`，以及 PoseAtlas 的 24 個正式視角。每個視角都必須有自己的素材、anchor 與遮擋資料。舊 v1 三姿勢包保留為升級輸入，並以官方範本一次升級為完整 v2 包；完整且名稱精確的 31 視角集合才具備整包允收資格。

每個 ensemble 都必須提供 `autonomous_profile`，明確標示適用溫度帶、天氣、墨寒當下心境、場合與排序權重。自主選裝使用單一決策器，遵守手動鎖定、六小時冷卻與雨雪／特殊節日安全優先；完整匹配待定時維持目前衣裝，衣裝變更保持可見且可追溯。自創新衣與流行趨勢搜尋是分開保存的開關，可能產生雲端費用，在使用者明確啟用後執行。趨勢資料的使用範圍限定為抽象特徵，第三方照片與設計留在包外；生成結果先進隔離區，完成 31 視角、角色身分、手部、遮擋、來源與授權稽核後才可封裝安裝。

自創衣裝預設至少間隔七天，最多保留 16 個已安裝包、5 個待修隔離工作與 6 GiB；使用者可在控制台調整已安裝數量及容量上限。達到上限時暫停生成並完整保留既有內容與使用者上傳的包。新衣成功套用後會留下「首次展示待辦」；使用者在場、看向墨寒、目前可接收發話且處於可互動狀態時，墨寒才以全身鏡位主動問新衣是否好看。成功說完後標記完成；使用者追問來源時，墨寒可用四語詞庫幽默表示是自己上網尋得靈感並改良，系統提示與內部標記持續留在內部範圍。

髮型的最小穩定 slot 為必要的 `back`、`front`，以及選用但跨全部 silhouette 必須一致的 `side-left`、`side-right`、`bangs`、`bun`、`ponytail`。每一 silhouette 都有自己的 anchor、z-order，並必須選擇核心白名單的 face-occlusion mask、hand occlusion 與 garment/collar occlusion 規則，以維持臉、手與衣領的正確遮擋。外掛可替換可見髮絲；核心頭骨、臉型、眼睛、嘴型、五官、膚色與身份輪廓由核心提供。

頭飾使用 `headwear` 素材 slot，並必須指定 `crown`、左右 `temple`、左右 `ear` 或 `back-head` attachment point，以及對應的核心安全遮罩。武器可含 `weapon` 與 `sheath` 層，placement 限背部、左右腰側或左右手；每個 silhouette 都必須提供手部、衣裝、髮型遮擋規則及 `back-harness`、`waist-sheath`、左右握持之一的 attachment／握持契約，避免漂浮或穿模。手持物 placement 限左右手，並要求每個 silhouette 的手部遮擋；可承載通用道具，不寫死節慶或角色。珠寶與前景效果各有獨立槽。所有類型都要求四語名稱，順序為繁體中文、簡體中文、英文、日文。

素體本身是素顏、髮髻收攏的裸身：外袍、散髮（含鬢髮）、銀髮飾與妝容全部是可獨立開關、可替換的圖層，全身 24 視角與半身 7 個輪廓採同一標準。妝容使用 manifest 的 `makeup` 集合與 `makeup` 選擇槽：每個 item 可有多個 variant，每個 variant 在全部 31 個 silhouette 各提供 `eyes`（眼線、眼影、睫毛與眉一起）、`cheeks`（腮紅）、`lips`（唇色／唇彩）三張透明 RGBA PNG，畫布與該 silhouette 完全相同（24 視角 1024×1536、7 個半身輪廓 1254×1254），anchor 固定為 0,0，另可宣告 `intensity`（0–1，預設 1）。執行期妝容固定疊在膚色之上、髮型／頭飾／衣裝之下，不受保護臉部遮罩阻擋，但只能落在 `assets/makeup-safe-regions.json` 為該 silhouette 定義的安全區（由分層 rig 的眼皮／眼線／眉、腮紅、唇圖層外框各自外擴 24／48／20 像素而得，以 `tools/build_makeup_safe_regions.py` 重建），並維持可見虹膜、牙齒與口腔完整；匯入與執行期只接受不透明像素完整位於安全區內的圖層。使用者在雲裳閣的妝容選單挑選項目與 variant，或選「素顏」；0–100% 濃淡滑桿在合成時乘上圖層 alpha，並與其他選擇一樣持久保存。內建妝容項目 `mohan.makeup.builtin`／`mohan-signature` 提供「原妝」（對齊四代外觀）與「淡雅」兩個 variant，全新設定檔預設為原妝；它由官方素材目錄 `assets/official-packs/` 提供並維持內建常駐，`assets/makeup/builtin/manifest.json` 是以 `tools/scaffold_makeup_pack_manifest.py` 產生、再以 `tools/build_outfit_pack.py` 封裝的範本，第三方純妝容套件（例如節慶妝）也照此製作，並走與衣裝完全相同的匯入、驗證、清單與移除流程。所選妝容套件若被移除，執行期回退到內建原妝並在雲裳閣提示一次。

官方預設外觀包 `mohan.official.blue-white-hanfu`（藍白漢服）隨程式出貨，與內建妝容 `mohan.makeup.builtin` 一樣以密封的 `.mohan-outfit` 放在官方素材目錄 `assets/official-packs/`；兩者都維持內建常駐與 id 唯一性。它含一件 `garment`（`hanfu-robe`／`blue-white`，後方視角已含白鞋）、一個 `hairstyle`（`loose-hair`／`ink-black`：散髮放在必要的 `front` slot，`back` 是合法的全透明圖層，因為產線切出的髮層本來就全部疊在衣袍之上）、一個 `headwear`（`silver-hairpiece`／`silver`，attachment `crown`、遮罩 `crown-safe`）與一個 ensemble `blue-white-hanfu`。素材是工作室產線以四代參考圖在二代素體 `assets/pose-atlas/v5-base/` 上重繪、再逐層相減得到的分層；`tools/assemble_official_default_pack.py` 把 31 個 silhouette 的分層對映到本格式、裁掉執行期允收範圍以外的像素（衣袍落在受保護臉部、髮飾落在眼唇、妝容跑出安全區；髮絲只裁掉「五官核心」——眼與口的骨架切層向外擴 8 px——且保留五官核心以外的臉框範圍，執行期再以 6 px 羽化遮罩淡出同一條邊界，所以髮絲會自然垂落在額頭與臉頰上，維持自然且連續的邊緣）並寫出逐 silhouette 的裁切報告，最後以 `tools/build_outfit_pack.py` 封裝；`light` 妝容是 `classic` 圖層的 alpha 乘以 0.55。全新設定檔與「還原內建預設」寫入的 `builtin` 哨兵維持不可移除、可還原的語意，但由 `domain/outfit_pack_official.py` 決定它畫什麼：官方包在場時衣裝／髮型／頭飾解析到 `blue-white-hanfu` ensemble、妝容解析到內建原妝；精簡建置省略官方檔案時，該槽安全解析為素體。雲裳閣的「墨寒造型預覽」與桌面伴侶走同一條執行期合成路徑（分層全身渲染器加上啟用中的外觀疊層），顯示的是已穿上所選衣裝、髮型、頭飾與妝容（含濃淡）的完整造型，依選擇簽章快取、在分頁顯示後以短計時器合成；合成未完成時安全解析為素體，並在雲裳狀態列明確呈現狀態。四個手勢表情（mock_scold、mock_hit_front、eureka_front、exasperated_front）及其說話／眨眼幀由 `domain/companion_animation_contract.py` 對映到各自的手勢 silhouette：執行期以該手勢原畫為底、套上該 silhouette 的圖層，再貼上嘴形與眼睛補丁。

Manifest 的 `source` 必須記錄 `kind`（`original`、`concept`、`reference-derived`）、作者、授權與 `reference_included: false`。參考作品可作靈感紀錄，封裝內容則限定為自有或獲准素材。封裝允收集合排除 Python、JavaScript、EXE、DLL、腳本、絕對／穿越路徑、符號連結、加密成員、解壓炸彈、超限尺寸，以及含 script、事件、`foreignObject`、外部 URL、CSS `url()`、`data:`、DTD 或 entity 的 SVG。

刪除使用 typed remove API。內建預設維持常駐；active 或 preview 引用的單項或 ensemble 在切換或還原內建後，才進入可刪除狀態。刪除前會再次驗證安全 pack ID、檔名與 archive manifest ID 完全一致，然後精確移除該自含單檔，其他包、核心本體與個人資料保持原狀。刪除後清單只呈現仍在場的包。只有存在且安全的 ID、無路徑穿越、識別完全相符與狀態完整時才執行；其餘狀態皆 fail closed。若保存設定稍後指向已遺失的包，解析 API 明確回報 `missing` 並維持目前有效外觀；解析會保持穩定、可見且使用目前格式，並維持 pack identity 的精確對應。四語刪除確認由 UI 主線負責。

素体本身是素颜、发髻收拢的裸身：外袍、散发（含鬓发）、银发饰与妆容全部是可独立开关、可替换的图层，全身 24 视角与半身 7 个轮廓采用同一标准。妆容使用 manifest 的 `makeup` 集合与 `makeup` 选择槽：每个 item 可有多个 variant，每个 variant 在全部 31 个 silhouette 各提供 `eyes`（眼线、眼影、睫毛与眉一起）、`cheeks`（腮红）、`lips`（唇色／唇彩）三张透明 RGBA PNG，画布与该 silhouette 完全相同（24 视角 1024×1536、7 个半身轮廓 1254×1254），anchor 固定为 0,0，另可声明 `intensity`（0–1，默认 1）。运行时妆容固定叠在肤色之上、发型／头饰／服装之下，不受保护脸部遮罩阻挡，但只能落在 `assets/makeup-safe-regions.json` 为该 silhouette 定义的安全区（由分层 rig 的眼皮／眼线／眉、腮红、唇图层外框各自外扩 24／48／20 像素而得，用 `tools/build_makeup_safe_regions.py` 重建），并维持可见虹膜、牙齿与口腔完整；导入与运行时只接受不透明像素完整位于安全区内的图层。用户在云裳阁的妆容菜单挑选项目与 variant，或选「素颜」；0–100% 浓淡滑块在合成时乘以图层 alpha，并与其他选择一样持久保存。内置妆容项目 `mohan.makeup.builtin`／`mohan-signature` 提供「原妆」（对齐四代外观）与「淡雅」两个 variant，全新配置文件默认为原妆；它由官方素材目录 `assets/official-packs/` 提供并维持内置常驻，`assets/makeup/builtin/manifest.json` 是用 `tools/scaffold_makeup_pack_manifest.py` 生成、再用 `tools/build_outfit_pack.py` 封装的模板，第三方纯妆容套件（例如节日妆）也照此制作，并走与服装完全相同的导入、验证、列表与删除流程。所选妆容套件若被删除，运行时回退到内置原妆并在云裳阁提示一次。

官方默认外观包 `mohan.official.blue-white-hanfu`（蓝白汉服）随程序出货，与内置妆容 `mohan.makeup.builtin` 一样以密封的 `.mohan-outfit` 放在官方素材目录 `assets/official-packs/`；两者都维持内置常驻与 id 唯一性。它包含一件 `garment`（`hanfu-robe`／`blue-white`，后方视角已含白鞋）、一个 `hairstyle`（`loose-hair`／`ink-black`：散发放在必需的 `front` slot，`back` 是合法的全透明图层，因为产线切出的发层本来就全部叠在衣袍之上）、一个 `headwear`（`silver-hairpiece`／`silver`，attachment `crown`、遮罩 `crown-safe`）与一个 ensemble `blue-white-hanfu`。素材是工作室产线以四代参考图在二代素体 `assets/pose-atlas/v5-base/` 上重绘、再逐层相减得到的分层；`tools/assemble_official_default_pack.py` 把 31 个 silhouette 的分层映射到本格式、裁掉运行时接收范围以外的像素（衣袍落在受保护脸部、发饰落在眼唇、妆容跑出安全区；发丝只裁掉「五官核心」——眼与口的骨架切层向外扩 8 px——并保留五官核心以外的脸框范围，运行时再以 6 px 羽化遮罩淡出同一条边界，所以发丝会自然垂落在额头与脸颊上，维持自然且连续的边缘）并写出逐 silhouette 的裁切报告，最后以 `tools/build_outfit_pack.py` 封装；`light` 妆容是 `classic` 图层的 alpha 乘以 0.55。全新配置文件与「还原内置默认」写入的 `builtin` 哨兵保持不可移除、可还原的语义，但由 `domain/outfit_pack_official.py` 决定它画什么：官方包在场时服装／发型／头饰解析到 `blue-white-hanfu` ensemble、妆容解析到内置原妆；精简构建省略官方文件时，该槽安全解析为素体。云裳阁的「墨寒造型预览」与桌面伴侣走同一条运行时合成路径（分层全身渲染器加上启用中的外观叠层），显示的是已穿上所选服装、发型、头饰与妆容（含浓淡）的完整造型，按选择签名缓存、在标签页显示后以短计时器合成；合成未完成时安全解析为素体，并在云裳状态栏明确呈现状态。四个手势表情（mock_scold、mock_hit_front、eureka_front、exasperated_front）及其说话／眨眼帧由 `domain/companion_animation_contract.py` 映射到各自的手势 silhouette：运行时以该手势原画为底、套上该 silhouette 的图层，再贴上嘴形与眼睛补丁。

Manifest 的 `source` 必须记录 `kind`（`original`、`concept`、`reference-derived`）、作者、许可与 `reference_included: false`。参考作品可作为灵感记录，封装内容则限定为自有或获准素材。封装接收集合排除 Python、JavaScript、EXE、DLL、脚本、绝对／穿越路径、符号链接、加密成员、解压炸弹、超限尺寸，以及包含 script、事件、`foreignObject`、外部 URL、CSS `url()`、`data:`、DTD 或 entity 的 SVG。

删除使用 typed remove API。内置默认维持常驻；active 或 preview 引用的单项或 ensemble 在切换或恢复内置后，才进入可删除状态。删除前会再次验证安全 pack ID、文件名与 archive manifest ID 完全一致，然后精确移除该自包含单文件，其他包、核心本体与个人数据保持原状。删除后列表只呈现仍在场的包。只有存在且安全的 ID、无路径穿越、身份完全相符与状态完整时才执行；其余状态都会 fail closed。若保存设置后来指向已丢失的包，解析 API 明确返回 `missing` 并保持当前有效外观；解析会保持稳定、可见且使用当前格式，并维持 pack identity 的精确对应。四语删除确认由 UI 主线负责。

各 ensemble は適用温度帯、天候、墨寒の現在の気分、場面、優先度を示す `autonomous_profile` を持ちます。自律選択は一つの決定器が手動ロック、六時間のクールダウン、雨雪や特別な日の緊急性を処理します。完全一致の判定中は現在の衣装を維持し、衣装変更は可視かつ追跡可能な状態を保ちます。自己生成と流行検索は別々に保存する、料金が発生し得る設定で、利用者が明示的に有効化した後に動作します。流行情報の使用範囲は抽象的特徴に限定し、第三者の写真やデザインはパック外に保持します。生成案は 31 視点、同一性、手、遮蔽、出所、ライセンスの監査を通るまで隔離されます。

自己生成は既定で七日以上の間隔を置き、インストール済み 16 パック、修復待ち隔離 5 件、合計 6 GiB を上限とします。インストール数と容量は設定できます。上限到達時は生成を一時停止し、利用者がアップロードしたパックを含む既存内容を完全に保持します。新衣装の適用後は初回披露を一件だけ保留します。利用者が在席して墨寒を見ており、発話を受け取れる対話可能な状態の時に、全身画角で似合うか尋ねます。正常に話し終えた後に完了を記録します。入手元を尋ねられた時は、四言語の台詞集を使い、ネットで着想を見つけ自分で手直ししたと冗談めかして答えられます。システムプロンプトと内部タグは内部範囲に保持します。

髪型の最小安定 slot は必須の `back`、`front` と、任意ながら全 silhouette で一貫させる `side-left`、`side-right`、`bangs`、`bun`、`ponytail` です。各 silhouette は固有の anchor と z-order、およびコア許可済み face-occlusion mask、hand occlusion、garment/collar occlusion 規則を持ち、顔、手、襟との正しい遮蔽を維持します。パックは見える髪を交換でき、コア頭骨、顔型、目、口、顔部品、肌、同一性輪郭はコアが提供します。

頭飾りは `headwear` 素材 slot を使い、`crown`、左右 `temple`、左右 `ear`、`back-head` attachment point と対応するコア安全マスクを指定します。武器は `weapon` と `sheath` 層を持てます。placement は背中、左右の腰、左右の手に限定し、各 silhouette に手、衣装、髪の遮蔽と `back-harness`、`waist-sheath`、左右 grip の attachment／把持契約が必要です。これにより浮遊や貫通を防ぎます。手持ち物は左右の手だけに配置し、各 silhouette の手遮蔽が必須です。特定の祝日や人物を固定せず一般道具を扱えます。宝飾と前景効果は独立 slot です。全種類に繁体字中国語、簡体字中国語、英語、日本語の完全な名称が必要です。

素体そのものはすっぴんで髪をお団子にまとめた素の身体です。上衣、下ろした髪（鬢の房を含む）、銀の髪飾り、メイクはすべて個別に切り替え・差し替えできるレイヤーで、全身 24 視点と半身 7 輪郭は同一基準に従います。メイクは manifest の `makeup` 集合と `makeup` 選択 slot を使います。item は複数の variant を持て、各 variant は 31 の silhouette すべてに `eyes`（アイライン・アイシャドウ・まつ毛・眉をまとめて）、`cheeks`（チーク）、`lips`（口紅／グロス）の透明 RGBA PNG を三枚提供します。キャンバスは silhouette と完全に同一（24 視点は 1024×1536、半身 7 輪郭は 1254×1254）、anchor は 0,0 固定で、任意の `intensity`（0–1、既定 1）を宣言できます。実行時のメイクは常に肌の上、髪型／頭飾り／衣装の下に重なり、保護顔マスクの対象外ですが、`assets/makeup-safe-regions.json` がその silhouette に定義する安全領域（レイヤー rig のまぶた／アイライン／眉、チーク、唇の切り出し外枠をそれぞれ 24／48／20 ピクセル拡張したもの。`tools/build_makeup_safe_regions.py` で再生成）にクリップされ、見えている虹彩、歯、口腔を完全に維持します。インポート時と実行時は、不透明ピクセルがすべて安全領域内にあるレイヤーだけを受け入れます。利用者は雲裳閣のメイクメニューで item と variant、または「すっぴん」を選びます。0–100% の濃さスライダーは合成時にレイヤーの alpha に掛け合わされ、他の選択と同じく永続保存されます。内蔵メイク項目 `mohan.makeup.builtin`／`mohan-signature` は「基本メイク」（第四世代の外観に合わせたもの）と「淡めメイク」の二つの variant を持ち、新規プロファイルの既定は基本メイクです。これは公式素材ディレクトリ `assets/official-packs/` から提供され、内蔵常駐を維持します。`assets/makeup/builtin/manifest.json` は `tools/scaffold_makeup_pack_manifest.py` で生成し `tools/build_outfit_pack.py` で封止するテンプレートで、第三者のメイク専用パック（例えば祝日メイク）も同じ手順で作り、衣装とまったく同じインポート、検証、一覧、削除の流れを通ります。選択中のメイクパックが消えた場合、実行時は内蔵の基本メイクへ戻り、雲裳閣で一度だけ通知します。

公式の既定外観パック `mohan.official.blue-white-hanfu`（藍白漢服）はアプリに同梱され、内蔵メイク `mohan.makeup.builtin` と同じく封止済みの `.mohan-outfit` として公式素材ディレクトリ `assets/official-packs/` に置かれます。どちらも内蔵常駐と一意の id を維持します。内容は `garment` 一着（`hanfu-robe`／`blue-white`、背面視点には白い靴を含む）、`hairstyle` 一つ（`loose-hair`／`ink-black`。下ろした髪は必須の `front` slot に入り、`back` は正当な全透明レイヤーです。パイプラインが切り出した髪はもともとすべて袍の上に重なっているためです）、`headwear` 一つ（`silver-hairpiece`／`silver`、attachment `crown`、マスク `crown-safe`）、そして ensemble `blue-white-hanfu` 一つです。素材はスタジオのパイプラインが第四世代の参照画を第二世代素体 `assets/pose-atlas/v5-base/` 上に描き直し、段階的に差し引いて得たレイヤーで、`tools/assemble_official_default_pack.py` が 31 の silhouette のレイヤーを本形式へ対応付け、実行時の受入範囲外にあるピクセル（保護された顔に掛かる袍、目と唇に掛かる髪飾り、安全領域を外れるメイク。髪は顔枠のうち「特徴コア」——目と口のリグ切り出しを 8 px 外へ広げた領域——だけを切り落とし、実行時は同じ境界を 6 px のフェザーで溶かすため、髪は額や頬に自然に掛かり、連続した境界を維持します）だけを切り落として silhouette ごとの切り落とし報告を書き出し、最後に `tools/build_outfit_pack.py` で封止します。`light` メイクは `classic` レイヤーの alpha に 0.55 を掛けたものです。新規プロファイルと「内蔵の既定へ戻す」が書き込む `builtin` センチネルは削除不可・復元可能という意味を保ちますが、何を描くかは `domain/outfit_pack_official.py` が決めます。公式パックがある間は衣装／髪型／頭飾りが `blue-white-hanfu` ensemble に、メイクが内蔵の基本メイクに解決され、縮小ビルドが公式ファイルを省略する場合、その slot は安全に素体へ解決します。雲裳閣の「墨寒スタイルプレビュー」はデスクトップの伴侶と同じ実行時合成経路（レイヤー全身レンダラーと有効な外観オーバーレイ）を通り、選択した衣装・髪型・頭飾り・メイク（濃さ込み）を着せた完成形を表示します。選択シグネチャごとにキャッシュし、タブ表示後に短いタイマーで合成し、合成未完了時は安全に素体へ解決し、雲裳の状態行に明示します。四つのジェスチャー表情（mock_scold、mock_hit_front、eureka_front、exasperated_front）とその発話／まばたきフレームは `domain/companion_animation_contract.py` でそれぞれのジェスチャー silhouette に対応付けられ、実行時はそのジェスチャー原画を土台にその silhouette のレイヤーを着せ、その後に口と目のパッチを貼ります。

Manifest の `source` は `kind`（`original`、`concept`、`reference-derived`）、作者、ライセンス、`reference_included: false` を記録します。参照作品は着想元として記録でき、同梱内容は所有または許諾済みの素材に限定します。パッケージ受入集合からは Python、JavaScript、EXE、DLL、スクリプト、絶対／横断パス、シンボリックリンク、暗号化メンバー、解凍爆弾、過大寸法、および script、イベント、`foreignObject`、外部 URL、CSS `url()`、`data:`、DTD、entity を含む SVG を除外します。

削除には typed remove API を使用します。内蔵既定は常駐を維持します。active または preview が参照する単項目や ensemble は、別の外観へ切り替えるか内蔵へ復元した後に削除可能状態となります。削除前に安全な pack ID を再検証し、ファイル名と archive manifest ID の完全一致を要求します。その後、対象の自己完結ファイルだけを正確に削除し、他パック、コア本体、個人データは元の状態を保ちます。削除後の一覧は、現在存在するパックだけを表示します。既存かつ安全な ID、横断のないパス、完全な識別一致、健全な状態を満たす場合だけ実行し、その他の状態は fail closed です。保存設定が後に欠落パックを参照した場合、解決 API は `missing` を明示し、現在の有効な外観を維持します。解決は安定かつ可視の状態を保ち、現行形式と正確な pack identity の対応を維持します。四言語の削除確認 UI は本体側が担当します。
